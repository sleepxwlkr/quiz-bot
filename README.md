# Квиз-бот для Telegram

Бот на Python 3.9+ и SQLite. Сторонние библиотеки и отдельный сервер базы данных не нужны. Вопросы приходят каждому участнику в личный чат с ботом. Интерфейс на русском языке.

## Запуск в Windows

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram, отправьте /newbot и получите токен нового бота.
2. В файле .env рядом с этим README заполните строку BOT_TOKEN=... Если файла нет, скопируйте .env.example под именем .env.
3. Дважды нажмите start.bat или выполните в PowerShell:

       Set-Location -LiteralPath 'D:\Учебная практика'
       py -3 -m quizbot

4. Откройте своего бота в Telegram, нажмите «Запустить» и введите ник.

На этой машине доступен Python 3.9 через py -3. При переносе на другую машину установите Python 3.9 или новее. В Linux/macOS аналогичная команда — python3 -m quizbot.

Бот работает, пока запущен процесс и доступен интернет. Ctrl+C останавливает процесс. Чтобы он отвечал круглосуточно, запускайте этот проект на постоянно включённом компьютере или сервере. При следующем запуске открытые комнаты и незавершённые игры получат статус «Отменена». Профили, банк вопросов и результаты завершённых игр сохраняются.

Не публикуйте токен. .env и файлы базы добавлены в .gitignore. Настоящий токен не нужно присылать в чат.

## Что реализовано

- Регистрация только по нику, 3–24 символа: буквы, цифры, пробел, дефис и подчёркивание. Ники уникальны без учёта регистра. Смена ника через `/nick`.
- Ссылки на аккаунты в результатах по постоянному Telegram ID; текст ссылки — игровой ник на момент старта игры.
- Одиночная игра с выбором настроек, личным результатом и быстрым повтором.
- Комнаты на 2–10 участников, включая создателя. Приглашение по ссылке или коду. Создатель выбирает тему, сложность, число вопросов и время ответа, затем запускает игру.
- Общие для комнаты вопросы, их случайный порядок и случайный порядок вариантов. Повторы внутри игры исключены. Участники проходят вопросы в своём темпе.
- Автоматические тайм-ауты и переходы, выход из игры с подтверждением.
- Итоги с местами, ссылками, очками, числом верных ответов и уникальным ID игры.
- Краткая история игр с кодом, датой, статусом, своим местом и очками.
- Таблица лидеров по итогам каждой игры в комнате с местами, никами и очками.
- Общий рейтинг за текущий месяц по местам в завершённых играх в комнатах.
- Управление банком вопросов через `/admin` в личном чате.

## Одиночная игра

В главном меню нажмите «Играть одному». По умолчанию бот предлагает 10 вопросов по всем темам, смешанную сложность и 60 секунд на ответ. При меньшем банке он предлагает 5 вопросов, если их хватает. Тему, сложность, количество вопросов и время можно изменить перед стартом.

После нажатия «Начать» сразу открывается первый вопрос. По окончании бот покажет число верных ответов, полученные и максимально возможные очки. Кнопка «Сыграть ещё» запускает новую попытку с теми же настройками. Кнопка «Выйти» открывает подтверждение и после него отменяет попытку.

В истории такие попытки отмечены как «Одиночная». Месячный рейтинг рассчитывается по играм в комнатах.

## Комнаты и таймеры

В меню «Создать комнату» доступны все темы или отдельная тема, лёгкая/средняя/сложная/смешанная сложность, 5/10/20/30 вопросов и 15/30/60/120 секунд. Число вопросов ограничивается наличием вопросов в выбранной категории. После выбора параметров нажмите «Создать» и передайте приглашение участникам. Они должны открыть личный чат с ботом; незарегистрированные игроки сначала выберут ник.

Коды комнат состоят из пяти случайных латинских букв и цифр, например S23J8. Для ручного ввода исключены похожие символы 0/O и 1/I/L. Регистр при вводе не важен: /join s23j8 и /join S23J8 означают одно и то же. Код уникален среди всей истории игр и не переиспользуется; при случайном совпадении бот генерирует другой. Старые длинные коды сохраняют работоспособность.

Состав и настройки фиксируются при старте. Присоединение после старта закрыто. Один пользователь участвует в одной незавершённой игре одновременно.

Срок ответа хранится в базе как абсолютное серверное время. Время начинается с активации вопроса сервером, поэтому задержка доставки Telegram входит в лимит. В сообщении показывается оставшееся время. Нажатие принимается по времени получения обновления процессом бота; время нажатия на телефоне Telegram для callback не передаёт.

Отсчёт штрафа за время начинается отдельно: после успешного ответа Telegram на отправку или обновление вопроса. Первые 10 секунд после этого баллы не уменьшаются. Это подтверждение публикации сообщения Telegram, а не прочтения его игроком. Повторный показ через /room и повторная отправка не сбрасывают время. Общий срок игры и тайм-ауты остаются абсолютными: задержка доставки не продлевает тест.

Бот использует одно активное обновляемое сообщение для каждого пользователя. Нажатие кнопки заменяет текст и клавиатуру текущего сообщения. Следующий вопрос заменяет предыдущий; после завершения на его месте появляется итог или ожидание остальных. Если у нового экрана нет кнопок, старая клавиатура очищается.

Команды и текстовый ввод показывают ответ внизу чата; прежняя панель удаляется, если это разрешает Telegram. Это также действует для ошибок ввода. Сообщения самого пользователя остаются в чате. ID активного сообщения сохраняется в базе; удалённое пользователем сообщение бот создаёт заново. Ранее отправленные сообщения, ID которых не сохранялись до этого обновления, не очищаются задним числом.

При нажатии «Создать комнату» настройки открываются прямо в нажатом меню. После отмены можно сразу начать настройку заново. Запоздалое завершение старого запроса не переключает панель обратно на старое сообщение. При быстрых переходах в исходящей очереди остаётся только последний экран для пользователя. После принятого ответа бот сразу обновляет экран. Ошибки кнопок показываются уведомлением Telegram.

Правильный или неверный ответ сразу открывает следующий вопрос. По истечении лимита записывается timed_out, 0 очков, и открывается следующий вопрос. Его срок отсчитывается от истёкшего срока предыдущего, чтобы задержка обработки не продлевала тест. 10 вопросов по минуте заканчиваются максимум через 600 секунд серверного игрового времени. Итоговое сообщение может прийти позже при задержке сети.

Если игрок заблокировал бота во время игры, его вопросы всё равно закроются по таймеру. После разблокировки он сможет посмотреть своё место и очки в истории.

Лобби действует 30 минут, затем отменяется. Создатель видит кнопку «Удалить»: после подтверждения лобби закрывается для всех, а у создателя открывается главное меню. Кнопка «Отмена» возвращает в лобби. Гости видят «Выйти»: меню комнаты заменяется вопросом «Точно хотите покинуть комнату?» без предупреждения об очках. Подтверждение освобождает место и открывает главное меню; оставшиеся участники получают обновлённый состав. Пока комната открыта, не заполнена и игра не началась, вышедший участник может снова зайти по прежней ссылке или коду.

После старта создатель — обычный участник: его выход не завершает игру остальных; удаление уже запущенной игры недоступно. В подтверждении выхода начавшейся игры объясняются последствия для очков. Если игра началась во время подтверждения выхода из лобби, бот сначала запрашивает новое подтверждение с этим предупреждением. Старое подтверждение не срабатывает после отмены выхода или повторного входа.

Выход после старта отмечает оставшиеся ответы как forfeited с 0 очков. Игрок располагается ниже завершивших. До общего завершения он не начинает другую игру.

## Очки и места

Максимумы сохранены: 15 очков за лёгкий вопрос, 20 за средний и 25 за сложный. Первые 10 секунд после подтверждённой публикации вопроса правильный ответ даёт весь максимум. Затем очки линейно уменьшаются; максимальный штраф составляет 50% максимума:

    M = 15, 20 или 25
    t = время с первого подтверждения публикации вопроса
    T = время от этого подтверждения до срока ответа
    до 10 секунд: очки = M
    после 10 секунд: очки = округление(M × (1 − 0,5 × (t − 10) / (T − 10)))

Очки округляются до целого, половина округляется вверх. Нижняя граница — половина максимума с округлением вверх: 8/10/13 очков. Поэтому штраф никогда не превышает 50%. Если из-за доставки до срока осталось 10 секунд или меньше, за время штрафа нет. Ошибка, тайм-аут и пропуск при выходе дают 0.

Пример среднего вопроса при полном окне в минуту: на 0–10 секундах — 20 очков, на 35-й — 15, непосредственно перед концом — 10. Ответ ровно в срок или позже уже считается просроченным и даёт 0.

В новых играх действует описанная выше формула. История показывает очки и места, сохранённые на момент завершения игры.

Среди завершивших сначала сравниваются очки, затем число верных ответов, затем меньшее суммарное время. Тайм-аут прибавляет полный лимит вопроса к времени для сравнения мест. Полное равенство даёт общее место: 1, 1, 3. Игроки, вышедшие досрочно, идут после завершивших, между собой сравниваются по тем же показателям.


## Команды и история

| Команда | Действие |
| --- | --- |
| /start, /menu | Главное меню |
| /create | Создание комнаты |
| /join КОД | Вход в комнату |
| /room | Лобби, текущий вопрос или ожидание остальных; время не сбрасывается |
| /leave | Подтверждение выхода |
| /nick | Смена ника |
| /history | История игр по 5 записей |
| /top | Общий рейтинг за текущий месяц |
| /help | Правила |
| /cancel | Сброс ввода/настроек без выхода из игры |

Таблица лидеров показывается всем участникам при завершении игры в комнате. В истории игрок видит свои игры, включая открытые комнаты и отменённые игры. Для завершённых игр указаны очки и место, если игра проходила в комнате. Дата определяется по UTC+5.

В главном меню кнопка «Общий рейтинг» показывает до 20 игроков за текущий месяц (UTC+5). За первое место начисляется 3 балла, за второе — 2, за третье — 1. Учитываются игры, завершённые в этом месяце, и только игроки, которые завершили игру и дали хотя бы один верный ответ. Игроки с одинаковым местом получают одинаковое количество баллов. При равной сумме в общем рейтинге место тоже общее. С началом нового месяца в таблицу попадают игры нового месяца.

Команда /room показывает актуальную игру новым сообщением внизу чата, а кнопка «Моя игра» или «Обновить» обновляет нажатое меню. Прежняя панель удаляется по возможности Telegram. В лобби отображаются код, настройки и участники; во время теста — текущий вопрос с кодом игры. Повторный вызов не меняет номер вопроса, срок ответа и момент начала начисления штрафа. После своего завершения или выхода игрок видит ожидание остальных без кнопки повторного выхода.

## Управление вопросами в Telegram

Добавьте в `.env` строку `ADMIN_IDS=` и впишите после знака равенства постоянные числовые Telegram ID администраторов через запятую. Остановите бота и запустите его снова, чтобы применить список. Пустой список закрывает доступ для всех. Права проверяются при открытии `/admin`, нажатии каждой административной кнопки и вводе текста в мастере. Игровой ник и имя пользователя Telegram на доступ не влияют. Для работы с банком не нужно регистрироваться как игрок.

Администраторы из `ADMIN_IDS` получают в личном чате уведомления о запуске и штатной остановке бота. Чтобы получать их, сначала откройте чат с ботом и нажмите «Запустить». При принудительном завершении процесса или потере связи сообщение об остановке может не прийти.

Отправьте `/admin` в личном чате с ботом. Сначала откроется список тем. Выберите тему, затем сложность. После этого бот покажет вопросы из выбранного раздела.

- **Темы.** Используйте «Создать тему» или «Переименовать тему» и подтвердите название. Пустую тему можно заполнить позже. Переименование обновляет название в банке и комнатах, где игра ещё не началась. Начатые и завершённые игры сохраняют своё название темы в базе.
- **Список вопросов.** Листайте страницы, ищите по фрагменту текста и фильтруйте по активности внутри выбранной темы и сложности. Поиск работает без учёта регистра, в том числе для кириллицы. Откройте вопрос, чтобы посмотреть ответы, пояснение и ключ для JSON.
- **Добавить вопрос.** Бот подставляет выбранную тему и сложность. Введите текст и варианты ответов по одному на строку, затем выберите верный вариант. Пояснение можно пропустить. Проверьте предпросмотр и подтвердите сохранение. Новый вопрос сразу включён.
- **Редактировать.** В карточке нажмите «Редактировать», выберите поле и проверьте предпросмотр. Если варианты ответов изменились, выберите верный вариант ещё раз. Если вопрос параллельно изменил другой администратор или импорт JSON, бот покажет актуальную версию и предложит открыть редактирование заново.
- **Включить или отключить.** Подтвердите изменение в карточке вопроса. Отключённый вопрос не попадает в подбор при запуске новых игр. Снимки вопросов и результаты уже начатых и завершённых игр сохраняются.
- **Удалить.** Нажмите «Удалить вопрос» в карточке или «Удалить тему» в списке тем и подтвердите действие. При удалении темы из банка исчезают все её вопросы, включая отключённые. Уже начатые игры продолжаются, история сохраняется. Удалённая тема недоступна при запуске игры в комнате, которая ещё ждёт старта.
- **Журнал изменений.** Здесь видны дата и время в UTC, Telegram ID администратора, номер вопроса или название удалённой темы и действие. Изменение банка и запись в журнале сохраняются вместе. Журнал охватывает действия из Telegram.

«Отмена» или `/cancel` закрывает мастер без сохранения и возвращает в админку. Чтобы выйти из неё, нажмите «Главное меню».

Вопрос может содержать до 1500 символов и от 2 до 6 вариантов, каждый до 150 символов. В Telegram название темы вводится одной строкой до 100 символов, пояснение может содержать до 1200 символов. «Все темы» уже используется как общий пункт выбора темы.

## База и импорт вопросов

По умолчанию база находится в data/quiz_bot.db. Путь меняется в .env через DATABASE_PATH. Схема — quiz_bot_schema.sql. База создаётся автоматически при первом запуске. Чтобы подготовить базу без подключения к Telegram, выполните команду.

    py -3 -m quizbot --init-db

Основные таблицы: users, games, game_participants, questions, game_questions, answers. Служебные таблицы: conversations для состояния меню и приглашений, settings для позиции в очереди Telegram, outbox для повторной доставки сообщений, ui_messages для ID обновляемых сообщений. Месячный рейтинг вычисляется при открытии из сохранённых мест.

Версия схемы — 8. При запуске бот автоматически добавляет признак режима игры. Старые игры сохраняются как игры в комнатах. Для баз версий 4–6 также выполняются миграции банка вопросов и журнала. Для баз версий 1–3 создаётся резервная копия вида `quiz_bot.before-v4-XXXXXXXX.db`. При ошибке миграция откатывается.

У каждой игры внутренний числовой game_id и публичный game_code, например S23J8. Короткий код отображается в приглашении, итогах и истории. Текст вопросов, варианты, правильный ответ, базовые очки и ник участника сохраняются снимками. Изменения исходного банка не меняют сыгранные игры.

**Основной банк вопросов хранится в SQLite.** При обычном запуске или `--init-db` бот один раз загрузит `data/questions.json`, если файл есть и база ещё не содержит вопросов. Пустую базу можно заполнить через `/admin` или импорт. Правки и удаления в Telegram сохраняются при перезапуске.

Чтобы загрузить дополнительный файл или явно применить правки из JSON, остановите бота и запустите импорт.

    py -3 -m quizbot --import-questions path/to/more_questions.json

Файл содержит массив объектов.

    [
      {
        "key": "my-topic-001",
        "topic": "Моя тема",
        "difficulty": "easy",
        "text": "Сколько будет 2 + 2?",
        "options": ["3", "4", "5", "6"],
        "correct": 1,
        "explanation": "2 + 2 = 4."
      }
    ]

Поле `correct` содержит номер варианта с отсчётом от нуля. Допустимые значения `difficulty` — `easy`, `medium`, `hard`. Поле `explanation` можно опустить. `key` должен быть уникальным и постоянным. Для вопросов, созданных в Telegram, бот назначает ключ автоматически и показывает его в карточке.

При совпадении ключа импорт заменяет содержание вопроса и название его темы данными из файла. Перед импортом проверьте, что в файле указаны актуальные названия тем. Тема с новым названием появляется в списке автоматически. Статус активности вопроса сохраняется. Новый ключ добавляет включённый вопрос. Удалённые ключи и записи для удалённых тем пропускаются. Чтобы снова заполнить тему с прежним названием, создайте её в `/admin` и используйте новые ключи. Записи, которых нет в файле, остаются в банке. Импорт проверяет весь файл перед записью.

Для резервной копии остановите бота и скопируйте файл базы вместе с существующими файлами -wal и -shm; надёжнее пользоваться SQLite backup API. Файл .lock — блокировка процесса, игровых данных в нём нет.

## Скорость ответа и диагностика

Получение обновлений идёт в отдельном потоке long polling. Ответ на пришедшую команду ставится на отправку сразу; ожидание следующего обновления не задерживает исходящее сообщение. До четырёх отправок в разные чаты выполняются параллельно. Все обращения к SQLite остаются в основном потоке.

HTTPS-соединения для исходящих запросов переиспользуются между работниками, в том числе соединение, прогретое при старте через getMe. Для long polling используется отдельное соединение, чтобы он не занимал соединение для ответов. Обычные HTTP-прокси поддерживают CONNECT; для HTTPS-прокси сохранён совместимый путь через urllib, где повторное использование соединений может быть недоступно.

Ограничение между сообщениями одному игроку остаётся 1,05 секунды; ожидание этого интервала не задерживает другие чаты. Один запрос может тормозить из-за маршрута до Telegram, VPN, прокси или установки нового TLS-соединения.

Для безопасного замера сети без отправки сообщений и без конкуренции с работающим ботом:

    py -3 -m quizbot --network-check

Команда делает пять запросов getMe и показывает длительность. Первый включает установку соединения, последующие обычно переиспользуют его. Это длительность запросов API, а не полный путь от команды в приложении Telegram до отображения ответа. Команда не выводит токен.

Для подробных времён установите LOG_LEVEL=DEBUG в .env и перезапустите бот. В консоли появятся длительности API-запросов и время сообщения в исходящей очереди. После изменения кода остановите прежний процесс через Ctrl+C и снова запустите start.bat; одновременно два экземпляра запускать нельзя.

## Надёжность и границы проверки

Обработка обновления и изменение игры выполняются одной транзакцией SQLite вместе с сохранением offset отдельно для ID Telegram-бота. Поэтому замена токена на токен другого бота не заставляет его пропускать обновления из очереди старого бота. Повторное обновление не создаёт ещё одну игру и не начисляет очки повторно. Первичный ключ ответа исключает второй ответ на тот же вопрос.

Пока бот работает, очередь повторяет отправку при сетевых ошибках и ограничении Telegram 429. Просроченные вопросы из очереди отбрасываются. При запуске очередь и незаконченный ввод очищаются. Место и очки доступны в `/history`, даже если бот не успел отправить итоги.

Запускайте один экземпляр на одну базу и один Telegram-токен. Проект использует long polling. При активном webhook запуск остановится с пояснением. Если этот токен раньше использовал другой проект, остановите его и удалите webhook через Bot API deleteWebhook с drop_pending_updates=false. Бот не удаляет чужой webhook автоматически.

Локальные проверки работают без токена и без сети:

    py -3 -m unittest discover -v

Проверяются регистрация, уникальность ников, права создателя, лимит комнаты, снимки вопросов, очки, повторные ответы, таймеры, отмена незавершённых игр при запуске, выход, места в игре, краткая история, приглашение до регистрации, повторные обновления и повтор доставки после 429. Реальную переписку с Telegram нужно проверить после добавления токена.

Для ручной проверки зарегистрируйте два аккаунта. Первый создаёт комнату на 5 вопросов по 15 секунд, второй входит по ссылке. После старта один отвечает, второй ждёт. Через 75 секунд заканчивается игровое время, оба получают таблицу лидеров с одним кодом, а в истории каждый видит своё место и очки. Если остановить бота посреди следующей игры и снова запустить, эта игра появится в истории со статусом «Отменена».

Документация Telegram: [Bot API](https://core.telegram.org/bots/api), [пригласительные ссылки и start payload](https://core.telegram.org/bots/features#deep-linking). Открытие ссылки на аккаунт по ID зависит от настроек приватности Telegram; игровой ник при этом отображается всегда.
