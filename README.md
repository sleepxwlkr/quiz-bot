# Квиз-бот для Telegram

Бот на Python 3.9+ и SQLite. Сторонние библиотеки и отдельный сервер базы данных не нужны. Вопросы приходят каждому участнику в личный чат с ботом. Интерфейс на русском языке.

## Запуск в Windows

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram, отправьте /newbot и получите токен нового бота.
2. В файле .env рядом с этим README заполните строку BOT_TOKEN=... Если файла нет, скопируйте .env.example под именем .env.
3. Дважды нажмите start.bat или выполните в PowerShell:

       Set-Location -LiteralPath 'D:\Учебная практика'
       py -3 -m quizbot

4. Откройте своего бота в Telegram, нажмите «Запустить» и введите ник.

На этой машине доступен Python 3.9 через py -3. При переносе на другую машину установите Python 3.9 или новее. В Linux/macOS аналогичная команда — python3 -m quizbot.

Бот работает, пока запущен процесс и доступен интернет. Ctrl+C останавливает процесс. Чтобы он отвечал круглосуточно, запускайте этот проект на постоянно включённом компьютере или сервере. При остановке прогресс не теряется, но игровые часы продолжают идти.

Не публикуйте токен. .env и файлы базы добавлены в .gitignore. Настоящий токен не нужно присылать в чат.

## Что реализовано

- Регистрация только по нику, 3–24 символа: буквы, цифры, пробел, дефис и подчёркивание. Ники уникальны без учёта регистра. Смена ника через профиль.
- Ссылки на аккаунты в результатах по постоянному Telegram ID; текст ссылки — игровой ник. В истории остаётся ник на момент старта игры.
- Комнаты на 2–10 участников, включая создателя. Приглашение по ссылке или коду. Создатель выбирает тему, сложность, число вопросов и время ответа, затем запускает игру.
- Дуэли: поиск среди ожидающих игроков с ближайшим рейтингом или вызов другу по ссылке. Автостарт при появлении второго участника. 10 вопросов по всем темам, смешанная сложность, 60 секунд на вопрос.
- Общие для комнаты вопросы, их случайный порядок и случайный порядок вариантов. Повторы внутри игры исключены. Участники проходят вопросы в своём темпе.
- Автоматические тайм-ауты и переходы, выход из игры с подтверждением, восстановление сроков после перезапуска.
- Итоги с местами, ссылками, очками, числом верных ответов и уникальным ID игры. В дуэли также изменение рейтинга.
- Профиль, средние показатели по режимам, история с листанием и разбор каждого ответа после завершения всей игры.
- Общая таблица рейтинга дуэлей. Результаты комнат на рейтинг дуэлей не влияют.

## Комнаты и таймеры

В меню «Создать комнату» доступны все темы или отдельная тема, лёгкая/средняя/сложная/смешанная сложность, 5/10/20/30 вопросов и 15/30/60/120 секунд. Число вопросов ограничивается наличием вопросов в выбранной категории. После выбора параметров нажмите «Создать» и передайте приглашение участникам. Они должны открыть личный чат с ботом; незарегистрированные игроки сначала выберут ник.

Новые коды комнат и дуэлей состоят из пяти случайных латинских букв и цифр, например S23J8. Для ручного ввода исключены похожие символы 0/O и 1/I/L. Регистр при вводе не важен: /join s23j8 и /join S23J8 означают одно и то же. Код уникален среди всей истории игр и не переиспользуется; при случайном совпадении бот генерирует другой. Старые длинные коды сохраняют работоспособность.

Состав и настройки фиксируются при старте. Присоединение после старта закрыто. Один пользователь участвует в одной незавершённой игре одновременно.

Срок ответа хранится в базе как абсолютное серверное время. Время начинается с активации вопроса сервером, поэтому задержка доставки Telegram входит в лимит. В сообщении показывается оставшееся время. Нажатие принимается по времени получения обновления процессом бота; время нажатия на телефоне Telegram для callback не передаёт.

Отсчёт штрафа за время начинается отдельно: после успешного ответа Telegram на отправку или обновление вопроса. Первые 10 секунд после этого баллы не уменьшаются. Это подтверждение публикации сообщения Telegram, а не прочтения его игроком. Повторный показ через /room и повторная отправка не сбрасывают время. Общий срок игры и тайм-ауты остаются абсолютными: задержка доставки не продлевает тест.

Настройки комнаты, лобби, вопросы и финал используют одно обновляемое сообщение для каждого участника. При выборе параметра изменяются его текст и кнопки. Следующий вопрос заменяет предыдущий; после завершения на его месте появляется итог или ожидание остальных. ID сообщения сохраняется в базе, поэтому перезапуск не создаёт ещё одну копию. Если пользователь удалил сообщение, бот создаст новое.

При нажатии «Создать комнату» настройки открываются прямо в нажатом меню. Команда /create открывает новое сообщение внизу чата; прежняя панель удаляется, если это разрешает Telegram. После отмены можно сразу начать настройку заново. Запоздалое завершение старого запроса не переключает панель обратно на старое сообщение.

Правильный или неверный ответ сразу открывает следующий вопрос. По истечении лимита записывается timed_out, 0 очков, и открывается следующий вопрос. Его срок отсчитывается от истёкшего срока предыдущего: задержка обработки или перезапуск не продлевают тест. 10 вопросов по минуте заканчиваются максимум через 600 секунд серверного игрового времени. Итоговое сообщение может прийти позже при задержке сети.

Если бот был выключен, при запуске он последовательно отмечает просроченные вопросы и показывает только актуальный вопрос либо итог. Пройденные дедлайны не запускаются заново. Если аккаунт заблокировал бота, игрок всё равно завершится по таймеру; результат доступен ему в истории после разблокировки.

Лобби и поиск дуэли действуют 30 минут, затем отменяются. Отмена до старта не влияет на статистику. Создатель видит кнопку «Удалить»: после подтверждения лобби закрывается для всех, а у создателя открывается главное меню. Кнопка «Отмена» возвращает в лобби. Гости видят «Выйти»: меню комнаты заменяется вопросом «Точно хотите покинуть комнату?» без предупреждения об очках. Подтверждение освобождает место и открывает главное меню; оставшиеся участники получают обновлённый состав. Пока комната открыта, не заполнена и игра не началась, вышедший участник может снова зайти по прежней ссылке или коду.

После старта создатель — обычный участник: его выход не завершает игру остальных; удаление уже запущенной игры недоступно. В подтверждении выхода начавшейся игры объясняются последствия для очков и, для дуэли, сдача. Если игра началась во время подтверждения выхода из лобби, бот сначала запрашивает новое подтверждение с этим предупреждением. Старое подтверждение не срабатывает после отмены выхода или повторного входа.

Выход после старта отмечает оставшиеся ответы как forfeited с 0 очков. Игрок располагается ниже завершивших; в дуэли это сдача. До общего завершения матча он не начинает другую игру — это также исключает одновременное изменение рейтинга в двух дуэлях.

## Дуэль с другом

Откройте «Дуэли» → «Вызвать друга» или отправьте /challenge. Бот создаст дуэль и покажет ссылку-приглашение и короткий код. Скопируйте ссылку и отправьте её другу самостоятельно. Друг открывает ссылку, нажимает «Запустить» и при необходимости выбирает ник. Когда он присоединится, оба участника автоматически получат первый вопрос.

По этой ссылке может присоединиться первый её получатель; персонального закрепления за конкретным аккаунтом нет. Создатель уже занимает одно из двух мест, переход по собственной ссылке не создаёт второго участника. После старта новые подключения закрыты.

Дуэль по приглашению не участвует в автоматическом подборе соперников. В меню «Дуэли» → «Найти соперника» остаётся обычный поиск. У обоих вариантов одинаковые вопросы по общему банку, настройки, начисление очков, рейтинг Elo и статистика режима «Дуэль». В ожидании второго участника приглашение действует 30 минут; отмена через /leave не меняет рейтинг.

## Очки и места

Максимумы сохранены: 15 очков за лёгкий вопрос, 20 за средний и 25 за сложный. Первые 10 секунд после подтверждённой публикации вопроса правильный ответ даёт весь максимум. Затем очки линейно уменьшаются; максимальный штраф составляет 50% максимума:

    M = 15, 20 или 25
    t = время с первого подтверждения публикации вопроса
    T = время от этого подтверждения до срока ответа
    до 10 секунд: очки = M
    после 10 секунд: очки = округление(M × (1 − 0,5 × (t − 10) / (T − 10)))

Очки округляются до целого, половина округляется вверх. Нижняя граница — половина максимума с округлением вверх: 8/10/13 очков. Поэтому штраф никогда не превышает 50%. Если из-за доставки до срока осталось 10 секунд или меньше, за время штрафа нет. Ошибка, тайм-аут и пропуск при выходе дают 0.

Пример среднего вопроса при полном окне в минуту: на 0–10 секундах — 20 очков, на 35-й — 15, непосредственно перед концом — 10. Ответ ровно в срок или позже уже считается просроченным и даёт 0.

Новые игры используют версию начисления 2. Игры, созданные до обновления, сохраняют версию 1 и прежний бонус 0–5, чтобы правила не менялись посреди матча. Уже сохранённые результаты не пересчитываются.

Среди завершивших сначала сравниваются очки, затем число верных ответов, затем меньшее суммарное время. Тайм-аут прибавляет полный лимит вопроса к времени для сравнения мест. Полное равенство даёт общее место: 1, 1, 3. Игроки, вышедшие досрочно, идут после завершивших, между собой сравниваются по тем же показателям.

В рейтинге дуэлей используется Elo, начальный рейтинг 1000, K=32. При равных рейтингах победа даёт +16, поражение −16. Ничья равных игроков даёт 0; при разных рейтингах очки могут измениться и за ничью. Два изменения всегда противоположны. Рейтинг не сбрасывается автоматически; сезоны в эту версию не включены.

## Профиль и история

| Команда | Действие |
| --- | --- |
| /start, /menu | Главное меню |
| /create | Создание комнаты |
| /join КОД | Вход в комнату |
| /duel | Выбор: поиск соперника или вызов другу |
| /challenge | Создать приглашение другу на дуэль |
| /room | Лобби, текущий вопрос или ожидание остальных; время не сбрасывается |
| /leave | Подтверждение выхода |
| /profile | Профиль и статистика |
| /nick | Смена ника |
| /history | История игр по 5 записей |
| /game КОД | Итог своей завершённой игры |
| /top | Топ-20 по рейтингу дуэлей |
| /help | Правила |
| /cancel | Сброс ввода/настроек без выхода из игры |

В общей статистике: игры, победы, общие первые места, сдачи, сумма и среднее очков, верные ответы и точность. Для каждого режима дополнительно: лучший счёт, среднее место и среднее время ответа.

В статистику входят только завершённые матчи, включая завершённые по таймерам. Единоличная победа и общее первое место считаются отдельно. Точность — отношение всех верных ответов ко всем вопросам игрока; тайм-ауты и сдача входят в знаменатель. Среднее время считается по фактически отправленным ответам, без тайм-аутов; это среднее по ответам, а не по средним отдельных игр.

История хранит и активные, и отменённые игры с соответствующими статусами. Просмотр итогов и разбора разрешён только участникам игры. Правильные ответы доступны после общего завершения, чтобы не передавать их участникам, которые ещё играют. Даты в истории показываются в UTC+5.

Команда /room показывает актуальную игру новым сообщением внизу чата, а кнопка «Моя игра» или «Обновить» обновляет нажатое меню. Прежняя панель удаляется по возможности Telegram. В лобби отображаются код, настройки и участники; во время теста — текущий вопрос с кодом игры. Повторный вызов не меняет номер вопроса, срок ответа и момент начала начисления штрафа. После своего завершения или выхода игрок видит ожидание остальных без кнопки повторного выхода. После общего завершения результаты доступны через /history.

## База и вопросы

По умолчанию база находится в data/quiz_bot.db. Путь меняется в .env через DATABASE_PATH. Схема — quiz_bot_schema.sql. База создаётся автоматически при первом запуске. Только создать базу и загрузить вопросы, без подключения к Telegram:

    py -3 -m quizbot --init-db

Основные таблицы: users, games, game_participants, questions, game_questions, answers. Служебные таблицы: conversations для состояния меню и приглашений, settings для позиции в очереди Telegram, outbox для повторной доставки сообщений, ui_messages для ID обновляемых сообщений. Представления user_mode_stats и user_overall_stats вычисляют статистику по истории.

Версия схемы — 3. При запуске базы версий 1 и 2 обновляются автоматически. Поле games.matchmaking различает общий поиск (public) и приглашение (invite); у комнат оно равно none. Старые дуэли сохраняются как public. Игроки, история, результаты и существующие коды сохраняются.

У каждой игры внутренний числовой game_id и публичный game_code, например S23J8. Короткий код отображается в приглашении, итогах и истории. Текст вопросов, варианты, правильный ответ, базовые очки и ник участника сохраняются снимками. Изменения исходного банка не меняют сыгранные игры.

В data/questions.json включены 60 стартовых вопросов: информатика и география, по 10 вопросов каждой сложности на тему. Для расширения отредактируйте файл или импортируйте дополнительный:

    py -3 -m quizbot --import-questions path/to/more_questions.json

Формат — массив объектов:

    [
      {
        "key": "my-topic-001",
        "topic": "Моя тема",
        "difficulty": "easy",
        "text": "Сколько будет 2 + 2?",
        "options": ["3", "4", "5", "6"],
        "correct": 1,
        "explanation": "2 + 2 = 4."
      }
    ]

correct — индекс с нуля, сложности — easy, medium, hard. key должен быть уникальным и постоянным. Совпадающий ключ обновляет исходный вопрос, новый — добавляет. При запуске штатный банк снова загружается из data/questions.json, поэтому его вопросы редактируйте в этом файле; дополнительные вопросы используйте с собственными ключами. Импорт проверяет формат до записи. Неактуальные вопросы можно отключить полем questions.is_active=0.

Для резервной копии остановите бота и скопируйте файл базы вместе с существующими файлами -wal и -shm; надёжнее пользоваться SQLite backup API. Файл .lock — блокировка процесса, игровых данных в нём нет.

## Скорость ответа и диагностика

Получение обновлений идёт в отдельном потоке long polling. Ответ на пришедшую команду ставится на отправку сразу; ожидание следующего обновления не задерживает исходящее сообщение. До четырёх отправок в разные чаты выполняются параллельно. Все обращения к SQLite остаются в основном потоке.

HTTPS-соединения для исходящих запросов переиспользуются между работниками, в том числе соединение, прогретое при старте через getMe. Для long polling используется отдельное соединение, чтобы он не занимал соединение для ответов. Обычные HTTP-прокси поддерживают CONNECT; для HTTPS-прокси сохранён совместимый путь через urllib, где повторное использование соединений может быть недоступно.

Ограничение между сообщениями одному игроку остаётся 1,05 секунды; ожидание этого интервала не задерживает другие чаты. Один запрос может тормозить из-за маршрута до Telegram, VPN, прокси или установки нового TLS-соединения.

Для безопасного замера сети без отправки сообщений и без конкуренции с работающим ботом:

    py -3 -m quizbot --network-check

Команда делает пять запросов getMe и показывает длительность. Первый включает установку соединения, последующие обычно переиспользуют его. Это длительность запросов API, а не полный путь от команды в приложении Telegram до отображения ответа. Команда не выводит токен.

Для подробных времён установите LOG_LEVEL=DEBUG в .env и перезапустите бот. В консоли появятся длительности API-запросов и время сообщения в исходящей очереди. После изменения кода остановите прежний процесс через Ctrl+C и снова запустите start.bat; одновременно два экземпляра запускать нельзя.

## Надёжность и границы проверки

Обработка обновления и изменение игры выполняются одной транзакцией SQLite вместе с сохранением offset отдельно для ID Telegram-бота. Поэтому замена токена на токен другого бота не заставляет его пропускать обновления из очереди старого бота. Повторное обновление не создаёт ещё одну игру и не начисляет очки повторно. Первичный ключ ответа исключает второй ответ на тот же вопрос.

Итоги отправляются через сохраняемую очередь. Сетевые ошибки и ограничение Telegram 429 приводят к повторной попытке, просроченные вопросы из очереди отбрасываются. Перезапуск между успешной отправкой сообщения и фиксацией отправки в базе может дать повтор сообщения; повтор очков или Elo при этом исключён. Абсолютно однократную доставку сообщения Telegram sendMessage не гарантирует.

Запускайте один экземпляр на одну базу и один Telegram-токен. Проект использует long polling. При активном webhook запуск остановится с пояснением. Если этот токен раньше использовал другой проект, остановите его и удалите webhook через Bot API deleteWebhook с drop_pending_updates=false. Бот не удаляет чужой webhook автоматически.

Локальные проверки работают без токена и без сети:

    py -3 -m unittest discover -v

Проверяются регистрация, уникальность ников, права создателя, лимит комнаты, снимки вопросов, очки, повторные ответы, таймеры, восстановление после перезапуска, сдача, Elo, доступ к разбору, приглашение до регистрации, повторные обновления и повтор доставки после 429. Реальную переписку с Telegram нужно проверить после добавления токена.

Простой ручной сценарий: два аккаунта регистрируются, первый создаёт комнату на 5 вопросов по 15 секунд, второй входит по ссылке. Создатель запускает; один отвечает, второй ждёт. Через максимум 75 секунд оба получают итог с одним ID; история и профиль показывают результат. Затем оба выбирают дуэль и проверяют изменение рейтинга. Ещё одну игру можно перезапустить на середине для проверки восстановления.

Документация Telegram: [Bot API](https://core.telegram.org/bots/api), [пригласительные ссылки и start payload](https://core.telegram.org/bots/features#deep-linking). Открытие ссылки на аккаунт по ID зависит от настроек приватности Telegram; игровой ник при этом отображается всегда.
